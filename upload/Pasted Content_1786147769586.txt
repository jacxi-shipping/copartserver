1. PROJECT OBJECTIVE
   ============================================================

Build a production-grade API-based Copart auction data platform.

The system receives Copart CSV files such as:

salesdata.csv

The CSV contains auction/vehicle information.

The system must:

1. Import the CSV into PostgreSQL.
2. Validate and normalize the data.
3. Prevent duplicate lots.
4. Update existing lots when newer data is imported.
5. Store all important CSV fields in PostgreSQL.
6. Provide REST APIs for accessing the data.
7. Provide exact lot-number lookup.
8. Provide VIN lookup.
9. Provide advanced vehicle search.
10. Provide upcoming-auction search.
11. Provide today's auction search.
12. Exclude past auctions by default.
13. Support advanced filters.
14. Support pagination.
15. Support sorting.
16. Support fuzzy search.
17. Support fast searching across millions of records.
18. Provide import job tracking.
19. Provide database statistics.
20. Provide API authentication.
21. Provide automatic API documentation.
22. Be Docker-ready.
23. Be production-ready.
24. Be easy for another frontend to consume.

14. DATE PARSING
================

20260814

0

Format:

YYYYMMDD

Convert:

20260813

to:

2026-08-13

If:

20260814

then:

2026-08-14

If:

0

then:

sale_date = NULL

sale_datetime_local = NULL

sale_datetime_utc = NULL

============================================================
15. SALE TIME PARSING
=====================

CSV times are usually:

HHMM

Examples:

1200

0930

1530

1700

Convert:

1200 -> 12:00:00

930 -> 09:30:00

1530 -> 15:30:00

Handle missing/invalid values safely.

============================================================
16. TIMEZONE HANDLING
=====================

The CSV may contain:

PST
PDT
MST
MDT
CST
CDT
EST
EDT

Use Python zoneinfo.

Map:

PST/PDT -> America/Los_Angeles

MST/MDT -> America/Denver

CST/CDT -> America/Chicago

EST/EDT -> America/New_York

Do not perform naive timezone conversion.

Build:

local datetime

then:

UTC datetime

Example:

20260814
1200
PDT

becomes:

2026-08-14 12:00:00 America/Los_Angeles

and:

2026-08-14 19:00:00 UTC

17. UPCOMING AUCTION LOGIC
==========================

This is a critical feature.

The system must determine whether an auction is still upcoming based on:

sale_datetime_utc

An auction is upcoming if:

sale_datetime_utc >= current UTC time

Therefore:

Yesterday:
EXCLUDE

Today before sale time:
INCLUDE

Today after sale time:
EXCLUDE

Tomorrow:
INCLUDE

Future:
INCLUDE

Unscheduled:
EXCLUDE by default
